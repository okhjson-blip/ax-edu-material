01 · FIT

사진 속 글자가 반복적으로
업무 입력값이 될 때 효과가 크다

적합한 출발점

반복되고 구조가 비교적 일정한 화면

  • 항목 이름과 값의 위치가 고정되거나 제한적
  • 사람이 여러 번 옮겨 적는 작업
  • 기준값·허용 범위와 비교할 수 있는 숫자
  • 오류가 나면 원본 사진으로 다시 확인 가능
먼저 검토할 조건

사진 한 장으로 판단하기 어려운 업무

  • 심한 반사·가림·움직임으로 글자가 보이지 않음
  • 한 화면에 같은 숫자가 여러 의미로 반복
  • 잘못 읽은 값이 즉시 설비 제어로 이어짐
  • 개인정보·보안 정책상 사진 저장이나 외부 전송 제한
선정 기준은 모델의 일반 점수보다 실제 현장 사진의 “필드별 오류”입니다.01 / FIT

01 · MEASUREMENT

인식률과 함께,
오류가 업무에 미치는 영향을 측정한다

필드 정확도

몇 칸을 정확히 읽었나?

사람이 확정한 정답과 인식 결과를 항목 단위로 비교합니다.

예: 100칸 중 97칸 일치 = 97%

업무 안전성

잘못된 알람 또는 놓친 변경은?

오탐과 누락을 따로 봅니다.
“읽지 못함”이 “일치”로 처리되면 안 됩니다.

운영성

현장에서 실제로 빠른가?

재촬영 비율, 작업자 수정 건수, 1장 처리 시간, 입력 절감 시간을 측정합니다.

시험 사진은 화면 종류, 기종, 조명, 반사, 촬영 각도를 나눠 확보하세요.01 / KPI

02 · LIMITS

현장 적용 전에는 화면 템플릿과
실패 경로를 먼저 검증한다

첨부 자료에 남은 한계
  • 반사가 심한 사진은 처리 시간이 13~15초로 늘어남
  • 기존 빈칸에 새 값이 들어와도 알람이 없는 경우
  • 정답·기준값의 사용자 검수가 아직 필요
  • 사내망 전용이지만 로그인 없는 조회·확정 방식
교육용 보완 제안
  • 기종·화면별 촬영 대상을 담당자와 확정
  • 반사·흐림·틀린 화면이면 저장 전 재촬영 안내
  • 빈칸→값 입력도 변경 규칙에 포함
  • 실운영 시 사용자 식별·권한·사진 보관 기간 설계
왼쪽은 첨부 자료의 확인 사항, 오른쪽은 이를 바탕으로 한 교육용 제안입니다.02 / NEXT

03 · MVP

최소 기능

  2. 정해진 값 칸 3개를 읽어 이름과 함께 표시

  • 반사·흐림 사진 3장

숫자는 교육용 최소 예시입니다. 실제 표본 수는 화면 종류와 현장 위험도에 맞춰 늘립니다.

03 · OPEN SOURCE OCR

PP-OCRv6로 HMI 판독 API를 만들고,
값 칸과 기준값을 연결한다

Python 연결 예시 · 로컬 CPU
from paddleocr import PaddleOCR

ocr = PaddleOCR(
    text_detection_model_name="PP-OCRv6_small_det",
    text_recognition_model_name="PP-OCRv6_small_rec",
    device="cpu",
    use_doc_orientation_classify=False,
    use_doc_unwarping=False,
    use_textline_orientation=False,
)
for page in ocr.predict("hmi.jpg"):
    page.save_to_json(save_path="output")

AI에게 구현시킬 순서

  1. 공식 설치 문서에 맞춰
    PaddlePaddle·PaddleOCR 환경 구성
  2. 앱 시작 시 모델을 한 번 로드하고,
    업로드 사진에서 문자·좌표·점수 추출
  3. 템플릿의 값 칸과 OCR 결과를 연결해
    숫자 형식·기준값을 검증

사내망 운영 전 모델을 미리 내려받고,
검증한 패키지·모델 버전을 기록합니다.

바이브 코딩 요청 예시
“PP-OCRv6 small을 사용하는 /ocr API를 만들어 줘.

03 · OPEN SOURCE OCR

EasyOCR로 한국어 라벨을 읽고,
품번·제품명 필드로 구조화한다

Python 연결 예시 · 한국어 + 영어
import easyocr

reader = easyocr.Reader(
    ["ko", "en"], gpu=False
)
rows = reader.readtext("label.jpg", detail=1)

for bbox, text, score in rows:
    print({
        "bbox": bbox,
        "text": text,
        "score": float(score)
    })

AI에게 구현시킬 순서

  1. easyocr와 호환되는 PyTorch 환경을
    구성하고 Reader를 재사용
  2. 문자 좌표를 사진 위에 표시하고,
    라벨의 품번·제품명 위치와 연결
  3. 숫자 전용 칸만 별도로 잘라
    allowlist를 적용한 결과와 비교

한국어 라벨 전체에 숫자 allowlist를
적용하면 제품명도 사라질 수 있습니다.

바이브 코딩 요청 예시

03 · OPEN SOURCE OCR

Tesseract로 숫자 한 줄을 읽고,
소수점과 허용 범위를 검사한다

Python 연결 예시 · 숫자 한 줄
from PIL import Image
import pytesseract
from pytesseract import Output

data = pytesseract.image_to_data(
    Image.open("value_crop.png"),
    lang="eng",
    config=(
        "--psm 7 "
        "-c tessedit_char_whitelist=0123456789.-"
    ),
    output_type=Output.DICT,
)

AI에게 구현시킬 순서

  1. Tesseract 실행 파일과 언어 데이터를
    설치하고 Python에서 실행 확인
  2. 값 칸을 자르고 기울기를 보정한 뒤
    한 줄 모드(--psm 7)로 판독
  3. 빈 결과·소수점 누락·허용 범위 이탈을
    작업자 확인 대상으로 표시

한국어 문서는 kor+eng를 검토하고,
숫자 전용 whitelist는 제거합니다.

바이브 코딩 요청 예시
“Tesseract로 잘라낸 압력 숫자를 읽는 함수를 만들어 줘.
0.50과 0.58, 소수점 누락을 시험하고, OCR 원문과 검증 결과를 나란히 보여 줘.”
전처리·PSM 설정 · pytesseract 연결 도구 · Windows에서는 실행 파일 경로 설정도 확인하세요.03 / TESS BUILD

OCR 결과 글자만 AI에 보내면, AI는 내용을 정리할 수 있지만 사진과 맞는지는 확인할 수 없습니다.
원본 사진도 보내면 AI가 다시 읽어 비교할 수 있습니다.

05 · OCR ENGINE VS AI API

고정 HMI는 로컬 OCR부터,
가변 양식은 AI API도 함께 시험한다

현장 조건먼저 검토할 방식선택 이유
화면과 값의 위치가 일정한 HMI로컬 OCR + 규칙 검증칸별 정확도와 변경 판정을 직접 관리
공급사마다 양식이 다른 문서·라벨이미지 입력 AI API항목의 의미와 배치 변화를 함께 해석
문자 추출 뒤 분류·설명이 필요한 업무OCR + AI 혼합 구성원문 근거와 의미 해석을 함께 활용
외부망 사용이 금지된 현장로컬 OCR 또는 사내 AI외부 서비스로 사진·텍스트 전송 불가
이 교육자료의 HMI 사례에 대한 제안:
로컬 OCR과 검증 규칙을 기본으로 두고 작업자가 확정합니다.
외부망 금지 조건을 유지한다면 외부 AI API 연계는 적용할 수 없습니다.
선택 기준: 항목별 정확성 · 누락과 오판정 · 작업자 수정량 · 응답 시간 · 전체 운영 비용05 / SELECT
