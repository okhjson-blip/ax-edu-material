SUPERPOWERS

brainstorming + writing-plans

obra/superpowers · 아이디어를 실행 가능한 계획으로 연결하는 2단계 핵심 스킬

brainstorming

아이디어 → 설계 문서

  • 막연한 아이디어를 대화로 다듬어 승인된 스펙 문서로 전환
  • 질문(1개씩) → 접근법 2~3개 제안 → 섹션별 디자인 제시
  • 복잡한 요청은 하위 프로젝트로 먼저 분해
  • 승인 전까지 구현 스킬 호출을 막는 하드 게이트 적용

writing-plans

설계 문서 → 실행 계획

  • 승인된 스펙을 2~5분 단위의 작은 작업으로 분해
  • 각 작업에 파일 경로 · 실제 코드 · 테스트 방법까지 명시
  • 컨텍스트 없는 엔지니어도 실행 가능하다고 가정하고 작성
  • 완료 후 subagent 실행 또는 배치 실행으로 이어짐
SUPERPOWERS

brainstorming은 모호한 아이디어를 합의 가능한 스펙으로 바꿉니다

사용법 — 아이디어와 원하는 결과를 말하고, 질문 → 대안 → 추천안 → 스펙 순서로 진행합니다.

이 서비스 아이디어를 설계 단계로 구체화해줘. 목표, 대상 사용자, 제약, 성공 기준을 먼저 질문하고, 서로 다른 사업 방향 3개를 비교한 뒤 추천안을 스펙 문서로 작성해줘. 아이디어: 1인 가구를 위한 AI 식단 · 장보기 앱
①해결하려는 문제
②대상 사용자
③제약 조건
④성공 기준

팁 — '기능을 만들어줘'보다 '스펙을 만들기 전에 질문해줘'가 적합합니다.

SUPERPOWERS

writing-plans는 스펙이 승인된 뒤에만 구현 계획으로 내려갑니다

01

스펙 확인

범위와 제약을 다시 읽습니다.

02

구조 확정

만들거나 바꿀 파일과 책임을 정합니다.

03

작업 분해

테스트 가능한 작은 단위로 나눕니다.

04

검증 설계

각 작업의 테스트 · 완료 기준을 명시합니다.

예시 요청

"승인된 아래 스펙을 구현 계획으로 바꿔줘. 파일, 작업, 테스트, 완료 기준을 포함해줘."

GRILL-ME

grill-me — 계획을 집요하게 검증하기

제작자 Matt Pocock · mattpocock/skills

  • 이미 존재하는 계획 · 스펙의 모든 측면을 인터뷰 형식으로 파고듦
  • 설계 트리의 각 분기를 따라가며 결정 간 의존성을 하나씩 해결
  • 질문마다 추천 답변을 함께 제시해 대화가 멈추지 않고 진행됨
  • 코드베이스를 읽어서 답할 수 있는 질문은 직접 확인 후 넘어감
주의

'X를 만들고 싶다' 수준의 막연한 아이디어에는 부적합합니다. 실행 전에 글로 된 스펙이나 설명이 먼저 준비되어야 합니다.

INTEGRATION

통합 워크플로우

막연한 아이디어에서 실행까지, 세 스킬의 연결

막연한 아이디어 → brainstorming → 스펙 문서 → grill-me → 검증된 스펙 → writing-plans → 실행 계획 → 구현

brainstorming이 아이디어를 스펙으로 만들고, grill-me가 그 스펙의 가정과 의존성을 압박 질문으로 검증한 뒤, writing-plans가 검증된 스펙을 2~5분 단위 실행 계획으로 쪼갭니다.

설치

트리거 방식

자연어 요청

"grill me on this spec"

슬래시 커맨드

$grill-me

진행 흐름

  • 결정 트리 분기마다 하나씩 질문
  • 코드베이스로 답 가능한 질문은 직접 확인 후 통과
  • 매 질문에 추천 답변을 제시해 진행 속도 유지
  • 고정된 질문 개수 없이 공유된 이해에 도달할 때까지 진행
CLAUDE

Grill-me 사용 예시

Grill me on this feature spec before I start building
Run grill-me on my plan for the auth refactor
Walk me through every decision in this architecture before I commit to it
BEFORE — grill-me 없이
  • 프롬프트 한 번 전달
  • 잘못된 가정에 기반한 계획 생성
  • 이후 계속 수정하며 시간 소모
AFTER — $grill-me 실행
  • 질문을 하나씩 받으며 함께 결정
  • 고려하지 못했던 맥락까지 반영
  • 공유된 이해 확보 → 적은 실수로 구현

Codex에서 Superpowers 사용하는 방법

brainstorming
