CHAPTER 01

왜 YOLO인가?

YOLO(You Only Look Once)는 사진 속에서 '무엇이(class) 어디에(위치, bounding box) 있는지'를 한 번에 찾아내는 객체 탐지(Object Detection) AI 모델입니다. PCB(회로기판) 사진 한 장을 넣으면, 결함의 종류와 정확한 위치를 박스로 표시해줍니다.

이번 튜토리얼에서 쓴 버전

  • YOLOv8n (nano) → YOLOv8s (small)로 실험 확장
  • 라이브러리: ultralytics (Python 패키지)
  • 실행 환경: Windows 노트북, GPU는 NVIDIA RTX 4070 Laptop (8GB)

YOLO 버전과 크기 정리

구분내용
버전 계보YOLOv1~v3(Redmon) → v4 → v5/v8/v11(Ultralytics) → v9,v10(연구기관) → 최신 YOLO26
크기(같은 버전 내)n(nano) < s(small) < m(medium) < l(large) < x(xlarge)
크기가 커지면정확도 ↑, 확신도(confidence) 더 뚜렷해짐, 대신 느려지고 GPU 메모리 더 씀
태스크 종류detect(객체탐지, 이번에 사용) / segment / pose / classify / obb

② 그다음 ultralytics 설치

pip install ultralytics --trusted-host pypi.org --trusted-host files.pythonhosted.org

숫자만 보면 완벽해 보이지만, 이는 '진짜 함정'이었습니다. 그림이 너무 단순해서 모델이 진짜 PCB의 복잡한 패턴이 아니라 단순한 도형 형태만 외워버린 것입니다. 실제 현장 사진에서는 전혀 통하지 않을 가능성이 높았습니다.

교훈: 합성 데이터의 높은 정확도는 '진짜 성능'이 아니라 '문제가 너무 쉬웠다'는 신호일 수 있습니다. 실전에 쓸 모델은 반드시 실제 데이터로 검증해야 합니다.

YOLO 라벨 포맷 이해하기

Roboflow에서 받은 라벨 파일(.txt)을 열어보면 이런 줄이 있습니다:

1 0.86171875 0.165625 0.021875 0.04375

각 숫자의 의미

위치값의미
1번째1클래스 번호 (data.yaml의 names 리스트에서 index 1번 = 두 번째 클래스)
2번째0.8617...박스 중심의 x좌표 (이미지 가로폭 대비 비율, 0~1)
3번째0.1656...박스 중심의 y좌표 (이미지 세로폭 대비 비율, 0~1)
4번째0.0219...박스 너비 (이미지 가로폭 대비 비율)
5번째0.0438...박스 높이 (이미지 세로폭 대비 비율)

핵심은 '정규화(normalized)'되어 있다는 것입니다. 픽셀 좌표가 아니라 0~1 사이 비율로 저장되어 있어서, 이미지 크기가 달라져도 라벨을 그대로 쓸 수 있습니다.

CHAPTER 06 · 1/2

모델 학습시키기 (Fine-tuning) · 학습 코드실습

'파인튜닝(fine-tuning)'이란 처음부터 학습시키는 게 아니라, 이미 대량의 일반 이미지(COCO 데이터셋)로 학습된 기본 모델(yolov8n.pt)을 가져와서, 우리 PCB 데이터로 '추가 학습'시키는 방법입니다. 훨씬 적은 데이터와 시간으로 좋은 성능을 낼 수 있습니다.

6-1. 전체 학습 코드

from pathlib import Path
from ultralytics import YOLO

def main():
    model = YOLO('yolov8n.pt')  # 기본 모델 불러오기
    model.train(
        data='roboflow_pcb_data/data.yaml',
        epochs=100,        # 전체 데이터를 100번 반복 학습
        imgsz=640,         # 입력 이미지 크기
        device=0,          # GPU 0번 사용 (CPU는 'cpu')
        batch=16,          # 한 번에 16장씩 묶어서 학습
        patience=30,       # 30 epoch 동안 개선 없으면 조기 종료
        optimizer='AdamW',
    )

if __name__ == '__main__':   # Windows에서는 필수!
    main()

CHAPTER 07 · 1/3

학습 중 만난 오류와 해결법 · 문제 1실습

실전에서는 크고 작은 오류를 반드시 만나게 됩니다. 실제로 겪었던 3가지 문제와 해결책입니다.

문제 1: SSL 인증서 오류로 모델/패키지 다운로드 실패

증상

[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed

원인: 회사 네트워크가 보안을 위해 SSL 트래픽을 가로채기(인터셉션) 때문

해결: pip 명령에 --trusted-host를 추가하거나, Python requests 라이브러리로 verify=False 옵션을 주고 수동 다운로드

CHAPTER 07 · 2/3

학습 중 만난 오류와 해결법 · 문제 2실습

문제 2: Windows에서 학습 시작 시 멀티프로세싱 오류

증상

RuntimeError: An attempt has been made to start a new process before
the current process has finished its bootstrapping phase...

원인: YOLO는 데이터를 빠르게 불러오려고 여러 개의 프로세스(worker)를 동시에 씁니다. Windows에서는 이 방식(spawn)을 쓸 때 실행 코드를 반드시 if __name__ == '__main__': 안에 넣어야 합니다. 안 그러면 자식 프로세스가 전체 스크립트를 처음부터 다시 실행하면서 무한히 충돌합니다.

해결: 학습 코드 전체를 main() 함수로 감싸고, 맨 아래에 다음 코드를 추가

if __name__ == '__main__':
    main()

CHAPTER 07 · 3/3

학습 중 만난 오류와 해결법 · 문제 3실습

문제 3: 최신 옵티마이저(muon)의 라이브러리 버그

증상

RuntimeError: view size is not compatible with input tensor's size and stride...

원인: 학습 시 'optimizer=auto'로 두면 라이브러리가 자동으로 최신 옵티마이저(muon)를 선택하는데, 이번에 사용한 ultralytics 버전에서 이 옵티마이저 자체에 버그가 있었습니다.

해결: optimizer를 명시적으로 안정적인 것으로 지정

model.train(..., optimizer='AdamW')

CHAPTER 09 · 1/2

Confidence(확신도)를 실무에 적용하는 법 · 비유로 이해하기

실무에서 흔히 하는 질문: "확신도를 0.99 이상으로 높일 수는 없나요? 그러면 사람이 다시 검사할 필요가 없어서 인건비가 줄어들 텐데요."

결론부터: 억지로 높이면 안 됩니다. 비유로 설명하겠습니다.

비유: 신입 검사원 이야기

AI 모델을 '방금 입사한 신입 검사원'이라고 생각해보세요. 이 검사원에게 '불량이라고 외칠 기준'을 정해줘야 합니다.

  • 기준을 너무 빡빡하게 잡으면 ("100% 확실할 때만 말해") → 신입은 그 정도로 확신하는 경우가 거의 없어서, 웬만하면 "정상입니다"라고 말해버립니다. → 진짜 불량을 놓치고 그대로 출하됨 (가장 위험)
  • 기준을 너무 느슨하게 잡으면 ("조금이라도 이상하면 다 말해") → 진짜 불량은 거의 다 잡지만, 멀쩡한 것도 불량이라 우김 → 사람이 매번 재확인 → 인건비 증가

정리 및 다음 단계

이번 튜토리얼에서 배운 핵심 포인트

  • 합성 데이터의 99% 정확도는 함정일 수 있다 — 반드시 실제 데이터로 검증할 것
  • YOLO 라벨은 정규화된 (class, x, y, w, h) 5개 숫자로 구성된다
  • 파인튜닝은 기본 모델(yolov8n.pt)에 우리 데이터를 추가 학습시키는 방식이다
  • GPU는 CPU 대비 약 7배 빠르며, 대량 데이터 학습에는 사실상 필수다
  • Windows 학습 코드는 반드시 if __name__ == '__main__': 으로 감싸야 한다
  • optimizer='auto'보다 'AdamW'처럼 명시적으로 지정하는 것이 안전할 때가 있다
  • confidence를 억지로 높이면 recall(놓치지 않는 능력)이 희생된다 — 3단계 판정 정책으로 대응
  • mAP 같은 종합 지표만 보지 말고, 실제 이미지로 직접 검증하는 과정이 반드시 필요하다

다음에 시도해볼 것들

  • yolov8s/m 학습을 끝까지 완료하고 nano와 정확도 비교
  • missinghole, shortcircuit, mousebite 클래스 데이터를 다른 공개 데이터셋(DeepPCB 등)에서 보강
  • 이미지 해상도를 640 → 1280으로 올려서 미세 결함 인식률 개선
  • 실제 생산 라인 카메라로 촬영한 이미지로 최종 현장 검증
  • confidence 3단계 판정 정책을 실제 검사 파이프라인(자동판정 + 재검토 대기열)으로 구현
