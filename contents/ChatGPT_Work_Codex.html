GLOSSARY

생소한 용어는 미리 알아두면 훨씬 편합니다

개발 경험이 없어도 괜찮습니다. Work · Codex 세션에서 나올 용어를 쉬운 말로 먼저 정리합니다.

Git

파일이 바뀐 기록을 저장해두는 서랍. 되돌리기가 쉬워집니다.

Diff

바뀌기 전과 후를 나란히 보여주는 비교 화면입니다.

PR (Pull Request)

“이렇게 바꿔도 될까요?”라고 정리해서 올리는 변경 제안서입니다.

CLI

마우스 클릭 대신 글자로 명령을 입력하는 화면입니다.

Terminal

CLI 명령을 입력하고 실행 결과를 보는 창입니다.

Sandbox

실제 자료에 영향 없이 안전하게 연습할 수 있는 격리 공간입니다.

안내 오늘은 이 용어들을 직접 실습하며 익히므로 외우지 않아도 됩니다.

FEATURE 01 · LIBRARY

라이브러리는 결과물을 다시 쓰게 만드는 개인 작업 보관함입니다

ChatGPT가 만든 문서 · PPT · 표 · 이미지와 업로드 파일을 보관하고, 검색해 다음 작업의 자료로 다시 사용하는 공간입니다.

1
왼쪽 메뉴에서 Library를 열고 파일명이나 내용으로 찾습니다.
2
파일을 열어 미리보기 · 다운로드 · 버전 정보를 확인합니다.
3
새 대화에서 파일을 선택하거나 ‘이 파일로 …’라고 후속 작업을 요청합니다.
추천 완성본은 ‘주제_용도_날짜’로 이름을 붙이고, 반복해서 쓸 템플릿은 별도 폴더로 구분하세요. (Library는 파일 재사용, Project는 장기 맥락 관리에 적합)
FEATURE 02 · PROJECTS

프로젝트는 같은 목표의 대화 · 파일 · 지침을 한 맥락으로 묶습니다

오래 이어지는 업무를 주제별로 정리하고, 관련 채팅 · 업로드 파일 · 연결 소스 · 프로젝트 지침을 여러 대화에서 공유합니다.

1
Projects에서 새 프로젝트를 만들고 목표가 드러나는 이름을 붙입니다.
2
Sources에 파일을 추가하고 반복 규칙은 Project instructions에 적습니다.
3
결과물마다 새 채팅을 시작해 맥락은 공유하되 대화 목적은 분리합니다.
추천 강의자료, 시장조사, 논문처럼 여러 산출물이 같은 자료를 쓰는 장기 업무에 사용하세요.
FEATURE 03 · SCHEDULED

예약 작업은 반복 업무를 정해진 시간이나 조건에 맞춰 실행합니다

보고서 갱신 · 모니터링 · 리마인더처럼 같은 작업을 한 번, 주기적으로, 또는 조건이 충족될 때 백그라운드에서 실행합니다.

1
일반 채팅에서 먼저 프롬프트를 수동 실행해 결과를 검증합니다.
2
무엇을 · 언제 · 어디에 보고할지 말하고 예약 생성을 요청합니다.
3
Scheduled에서 실행 기록을 확인하고 범위 · 도구 · 주기를 조정합니다.
추천 주간 동향 요약, 마감 알림, 승인 대기 상태 확인처럼 결과 기준이 명확한 일부터 시작하세요.
FEATURE 04 · PLUGINS

플러그인은 ChatGPT에 외부 서비스와 반복 업무 능력을 연결합니다

플러그인은 스킬 · 커넥터 · MCP 도구 등을 묶어 Google Drive, Slack, GitHub 같은 서비스의 정보를 읽거나 지원되는 작업을 수행하게 합니다.

1
Plugins에서 필요한 플러그인을 검색하고 상세 권한을 확인합니다.
2
설치 후 서비스 연결이 필요하면 로그인하고 최소 권한만 승인합니다.
3
새 채팅에서 @플러그인명과 함께 자료 위치 · 원하는 결과를 구체적으로 요청합니다.
추천 자료 검색은 Drive, 협업 요약은 Slack, 코드 작업은 GitHub처럼 원본이 있는 서비스부터 연결하세요.
FEATURE 05 · IMAGES

이미지는 설명만으로 만들고, 참조 이미지를 붙여 원하는 부분만 수정합니다

ChatGPT에서 배너 · 일러스트 · UI 자산 등을 생성하거나 기존 이미지를 참조해 추가 · 삭제 · 스타일 변경을 자연어로 요청할 수 있습니다.

1
용도 · 주제 · 구도 · 스타일 · 크기 · 금지 요소를 1~3문장으로 설명합니다.
2
수정할 때 참조 이미지를 첨부하고 ‘바꿀 것’과 ‘유지할 것’을 나눠 말합니다.
3
확대 보기나 Canvas에서 영역별 피드백을 주고 최종본을 다운로드합니다.
추천 첫 요청에서 완벽함을 기대하기보다 구도 → 내용 → 글자 · 세부 순서로 2~3회 다듬으세요.
FEATURE 06 · SITES

Sites는 아이디어를 바로 실행 가능한 웹사이트와 앱으로 배포합니다

프롬프트나 호환되는 기존 프로젝트에서 웹사이트 · 대시보드 · 내부 도구 · 게임을 만들고, OpenAI 호스팅으로 저장 · 수정 · 공유합니다.

https://ax-consulting-edu.okhjson.chatgpt.site/
1
프롬프트에 ‘website’ 또는 @Sites를 명시합니다. (예: ChatGPT Sites로 내부 프로젝트 관리 사이트를 만들어줘)
2
사용자 · 목적 · 핵심 행동 · 사용할 정보 · 저장 필요 여부를 설명합니다.
3
미리보기에서 기능을 검토하고 수정한 뒤 공개 범위를 정해 공유합니다.
추천 행사 안내, 신청 폼, 프로젝트 현황판처럼 화면과 상호작용이 필요한 결과물에 사용하세요.
FEATURE 07 · GPTS

GPT는 지침 · 지식 · 기능을 결합한 나만의 전문 ChatGPT입니다

반복되는 역할과 답변 규칙, 참고 문서, 사용할 기능을 미리 구성해 특정 업무에 일관되게 답하는 맞춤형 ChatGPT를 만듭니다.

1
Explore GPTs에서 기존 GPT를 시험하거나 Create를 선택합니다.
2
이름 · 목적 · 지침 · 지식 파일 · 사용 기능을 설정하고 예시 질문을 넣습니다.
3
대표 질문 5~10개로 정확성 · 거절 기준 · 출처 사용을 테스트한 뒤 공유 범위를 정합니다.
추천 FAQ 응답, 글쓰기 코치, 사내 규정 안내처럼 입력과 출력 형식이 반복되는 개인 업무부터 만드세요.

CONCEPT

Codex는 답변보다 “프로젝트의 실제 변경”을 만듭니다

일반 Chat

질문에 답하고 문장을 만듭니다. 로컬 프로젝트 파일을 직접 바꾸는 작업은 기본 목적이 아닙니다.

Codex 화면

선택한 폴더를 읽고 → 계획하고 → 파일을 수정하고 → 명령과 테스트로 검증합니다.

풀 리퀘스트

기능 설명

Codex가 생성했거나 연결된 코드 저장소의 Pull Request 목록을 한 곳에서 확인하는 기능. 리뷰 상태와 병합 여부를 추적합니다.

예시

“로그인 버그 수정 PR #128”이 “리뷰 대기” 상태로 표시되며, 클릭 시 연결된 저장소(GitHub 등)의 PR 상세 화면으로 이동합니다.

예약

기능 설명

특정 시간 또는 주기로 반복 실행할 작업을 등록해두는 기능. 원하는 주기로 Codex가 자동으로 작업을 수행하도록 예약합니다.

예시

“매일 오전 9시에 어제 커밋 내역을 요약해줘”처럼 등록해두면, 별도 요청 없이 정해진 시각에 자동 실행됩니다.

플러그인

기능 설명

외부 서비스·도구와 Codex를 연동하기 위한 확장 기능. 필요한 플러그인을 추가·제거해 작업 범위를 넓힐 수 있습니다.

예시

Slack 플러그인 연결 시 작업 완료 알림을 채널로 전송하거나, Jira 플러그인으로 이슈를 자동 생성할 수 있습니다.
MAIN PANEL

추천 카드

새 작업을 시작할 때 “무엇을 만들까요?” 문구와 함께 자주 쓰는 요청 4가지를 빠르게 선택할 수 있습니다.

APPROVE

승인 창에서는 대상 · 행동 · 영향을 확인합니다

2

STOP: 이해되지 않으면 Deny 후 설명을 요청한다.

실습 2

실습: 연습용 폴더에서 첫 요청 보내보기

목표: 실제 업무 폴더가 아닌 연습용 복사본 폴더로 첫 요청을 실행해봅니다.

1
Codex 화면에서 새 세션을 만들고,
연습용 폴더(회의록이나 문서 모음)를 선택합니다.
2
작업 폴더의 간단한 회의록을 저장합니다.
3
입력창에 “이 폴더의 파일들을 읽고,
핵심 내용을 summary.md 파일로 정리해 줘”라고 요청합니다.
4
Chat 패널에서 진행 상황을 지켜보고,
결과가 나오면 File 패널에서 summary.md를 열어 확인합니다.
TIP 요청은 한 번에 하나의 결과물만, 검토하기가 훨씬 쉽습니다.
실습 3

실습: Diff를 검토하고 승인해보기

목표: Codex가 만든 변경을 Diff 패널에서 확인하고, 이해한 뒤에만 승인합니다.

1
실습 2에서 만든 summary.md에
“표 형식으로 다시 정리해 줘”라고 추가 요청합니다.
2
Codex가 변경을 시작하면 승인 창에서
대상 파일과 실행 내용을 먼저 읽습니다.
3
승인 창에서 대상 파일과
바뀌는 내용을 다시 확인합니다.
4
Diff 패널을 열어
+ 추가된 줄과 - 삭제된 줄을 확인합니다.
5
이해된 변경이면 Allow,
이해되지 않으면 Deny 후 이유를 물어봅니다.
TIP 승인은 “빠르게”보다 “이해하고” 누르는 것이 안전합니다.
RESULT

혼자 할 때와 Codex와 함께할 때, 무엇이 달라지나요

직접 정리할 때
반복 작업

회의록을 열어 하나씩 읽고,
담당자 · 기한을 직접 표로 옮겨 적습니다.
파일이 많아질수록 시간이 늘어납니다.

Codex와 함께할 때
요청 1번 + 검토

요청 한 번으로 초안이 만들어지고,
사람은 Diff에서 결과만 검토 · 승인합니다.
승인한 내용만 실제 파일에 반영됩니다.

핵심 ‘시간 단축’이 아니라 ‘검토자로서의 역할 전환’입니다. 최종 확인은 항상 사람이 합니다.

SECURITY

회사 데이터를 다룰 때는 이 원칙을 지킵니다

AI 도구도 회사의 보안 · 개인정보 정책을 그대로 따릅니다.

이렇게 합니다
  • 연습은 항상 복사본 폴더에서 시작합니다.
  • 고객 · 개인정보가 포함된 파일은 먼저 회사 정책을 확인합니다.
  • 승인 창에서 대상과 영향을 직접 읽고 승인합니다.
  • 중요한 작업 전에는 Git이나 백업으로 되돌릴 방법을 준비합니다.
이렇게 하지 않습니다
  • 출처 모르는 폴더/홈 디렉터리를 신뢰 폴더로 등록하지 않음
  • 이해하지 못한 변경을 “일단 승인”하지 않음
  • Full access 권한을 일반 업무 PC에서 사용하지 않음
  • 외부 연동 기능을 필요 이상으로 연결하지 않음

SUMMARY

ChatGPT · Work · Codex는 업무의 길이와 파일 접근 범위로 나뉩니다

ChatGPT

짧은 대화 · 결과물 제작
• Library/Projects로 결과물 재사용
• Images · Sites로 콘텐츠 제작
• GPTs로 반복 업무 재활용

Work

장시간 에이전트 · 업무 자동화
• 연구 · 파일 · 앱 연동 작업 수행
• Scheduled로 반복 작업 예약
• Store에서 목적에 맞는 앱 선택

Codex

로컬 파일 직접 편집
• 선택한 폴더를 직접 읽고 수정
• Diff와 PR로 변경 검토
• CLI 스크립트와 자동화 확장

결과물만 필요하면 ChatGPT, 여러 단계의 조사·자동화가 필요하면 Work, 실제 코드·파일을 직접 바꿔야 하면 Codex를 선택하세요.
